# Review: README.md, CHANGELOG.md, LLM-CONTEXT-TRANSFER.md (reviewer "readme")

## Summary
README install and core Python/CLI basics work (quick start, decorator, `session.span()`, `trace --tree`, `claude init/validate`, RPA read endpoints all ran). But it has serious problems: (1) `pip install 'lctl[dashboard]'` (no git URL, README:619) is the exact dependency-confusion hazard the repo fixed elsewhere (commit 922bd43); (2) "Dashboard Security" overstates protection: API-key auth covers only `/api/rpa/*` (verified: `/api/chains`, `/api/chain/*`, `/api/events/emit` stay open with `LCTL_REQUIRE_API_KEY=true`), the CLI default binds `0.0.0.0`, port in examples is wrong (8000 vs 8080); (3) several integration examples are broken (OpenAI Agents `run_config`, PydanticAI `tracer.trace`, Semantic Kernel `trace_kernel(kernel, tracer)`), the "zero-config auto-instrumentation of frameworks" claim is false, and webhooks are registered but never delivered. LLM-CONTEXT-TRANSFER.md is a frozen v4.0 design doc: no 4.1/4.2 content, it documents nonexistent commands/modules (`lctl validate`, `lctl convert`, `lctl.claude`, `enable_lctl`) and unimplemented features (decay, consensus, fact store, contracts) as if real. CHANGELOG is structurally fine but misses the 2026-01-23 features, has a split list, nonstandard heading, dead compare link, and dubious 4.0.0 date.

All CLI/Python runs done in `.../docs-audit/readme/` with repo venv; SDK check for openai-agents done by downloading wheel 0.23.1 into scratch (not repo venv). Framework integrations otherwise verified by source reading.
